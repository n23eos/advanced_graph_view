# Нагрузочная проверка 10000 узлов

Дата: 2026-10-20. Кандидат: 0.10.1, ветка `codex/release-polish`.

## Результат

Браузерный нагрузочный сценарий PASS. Реальные `GraphRenderer` и `LayoutClient` отрисовали синтетический граф из 10000 узлов и 29956 рёбер. Раскладка выполнялась в реальном Web Worker, одновременно с ней главный поток сохранял медиану 59.9 fps. После завершения раскладки scripted pan и zoom также сохранили медиану не ниже 58.8 fps. Ошибок страницы, необработанных Promise rejection, длинных кадров свыше 33 мс и остановок вкладки не зарегистрировано.

Для выпуска 0.10.1 нагрузочная проверка не выявила блокера. Полная раскладка занимает около 11 секунд, а интервал выдачи worker tick имеет p95 86.2 мс. Это заметная длительность начальной стабилизации большого графа, но она не блокирует интерфейс: renderer сглаживает промежуточные позиции и сохраняет частоту кадров. Результат не является доказательством производительности внутри Obsidian на любом устройстве или любом vault.

## Стенд и методика

- `bench/bench.ts`, собранный командой `node bench/build.mjs`.
- Локальный сервер на `127.0.0.1`.
- CUA in-app browser корневого агента, реальный WebGL renderer PixiJS и Blob Worker из текущего `LayoutClient`.
- Детерминированный синтетический vault: 10000 заметок и целевой лимит 30000 связей. После удаления self-links модель содержит 29956 рёбер.
- 4 секунды замера `requestAnimationFrame` во время активной раскладки.
- Ожидание фактического сообщения `end` от layout worker, максимум 30 секунд.
- После остановки worker: `fitAll`, затем по 4 секунды scripted pan и zoom через штатные pointer и wheel events.
- Кадры с паузой более 500 мс учитываются отдельно как остановки вкладки и не смешиваются с frame timing. В этом прогоне таких кадров не было.

## Сравнение с предыдущей проверкой

В отчёте от 2026-10-02 зафиксированы 10000 узлов, 29956 рёбер и 127 мс до строки `first frame after init`. Старый harness записывал эту строку сразу после `layout.start()` и не ждал сообщения worker, поэтому 127 мс нельзя сравнивать с текущими 149.1 мс первого реального worker frame.

Отдельный CPU benchmark от 2026-10-02 измерял один 2D tick layout engine без PixiJS и межпоточной передачи: 27.150 мс для 10000 узлов и 40220 рёбер. Текущий браузерный интервал worker tick 47.3 мс включает pacing, вычисление, снимок координат и доставку сообщения для графа с 29956 рёбрами. Эти величины описывают разные участки и не доказывают ни ускорение, ни регрессию.

Перед расширением harness выполнен контрольный CUA-прогон прежнего сценария на текущем кандидате: pan 60.6 fps, frame median 16.50 мс, p95 21.90 мс; zoom 58.8 fps, frame median 17.0 мс, p95 22.8 мс; PASS. Расширенный прогон согласуется с ним.

## Реально выполненные проверки

- `node bench/build.mjs`: PASS.
- `npm run typecheck`: PASS.
- CUA in-app browser: расширенный сценарий завершён с `bench PASS`, результат получен из DOM и `RESULT_JSON`.
- Визуальная отрисовка графа подтверждена в CUA. Pan и zoom вызваны штатными событиями стенда.
- CUA Chrome extension отдельно воспроизвёл отсутствие WebGL в этой среде и показал ожидаемую ошибку PixiJS `No available renderer for the current environment`. Для измерений использован CUA in-app browser с доступным WebGL; ошибка Chrome extension не относится к runtime плагина.

## Ограничения

- Это синтетический browser harness с реальными renderer и worker, но без Obsidian API, вкладок Electron и пользовательского vault.
- Стенд проверяет 2D режим. 3D раскладка 10000 узлов заново не измерялась.
- Один расширенный прогон не задаёт статистическую baseline для разных машин. Сравнимого сохранённого baseline с той же методикой нет.
- Размер viewport задавался текущим окном CUA; отдельная матрица разрешений в этой нагрузочной проверке не запускалась.
- Потребление GPU и heap не измерялось.
